# v0.2 Release Notes

## Last Singularity v0.2 — Authority And Three Foundation

v0.2 turns Last Singularity from a rich prototype into a product-shaped game foundation. The game is still pre-public-playtest, but the central architecture is now legible: an authoritative sim owns run truth, a local renderer owns presentation, content lives in shared manifests, and the default renderer direction is Three.js layered over the ASCII fabric.

## Player-Facing Summary

You fly through a collapsing universe rendered as an ASCII fluid field. Thrust costs delta-v. Currents, gravity wells, stars, and slingshot anchors are not background effects; they are the routes. You loot wrecks, manage signal, dodge rivals and the Inhibitor, and decide whether another salvage pass is worth the exit risk.

## Major Changes

### Three.js Is Now The Product Renderer Direction

- The default renderer target is `?renderer=three`.
- Three owns a first-class top-down 3D scene with an orthographic camera, z-layered backdrop/fabric/entity/foreground groups, pooled dynamic meshes, and screen-space presentation.
- Composer and Three now share the `fluid-canvas` WebGL2 context.
- The old CPU bridge canvas and per-frame `CanvasTexture` upload path are gone.
- Renderer fixtures assert `sharedContext: true`, `canvasUploads: 0`, pooled meshes, world layers, semantic layers, and the top-down camera contract.

### The Sim/Renderer Split Is No Longer Aspirational

- Normal local launch commands start the authority stack.
- `npm run stack`, `npm start`, and `npm run stack:browser` all start the local host stack.
- Client-only play is explicitly `npm run stack:sandbox`, and it clears stored sim URLs so it cannot masquerade as product play.
- Remote-authority mode is the architectural truth path. The browser sends inputs; the sim owns run outcomes.

### Movement Became An Economy

- The old free-thrust prototype model is now historical.
- The ship has delta-v capacity, burn efficiency, regen, and regen boost.
- Brake is a real reverse-thrust verb with fuel cost.
- Slingshotting is an explicit designed action, not accidental gravity curvature.
- Server-authoritative slingshot engagement, energy, release, and chain state are shipped and tested.

### PlayerBrain And Hull Identity Are Real

- Five hulls exist in shared content: Drifter, Breacher, Resonant, Shroud, and Hauler.
- PlayerBrain resolves hull, rig, profile, and equipped-item coefficients for the authoritative server.
- Ability state is included in authoritative snapshots and HUD presentation.
- Several hull abilities are server-side behaviors, not only HUD descriptions.

### The Run Has More Persistent Shape

- Profiles, save slots, vault behavior, inventory shape, run results, chronicle records, and echo wreck foundations exist.
- Loot tiers, wreck age value scaling, consumables, item coefficients, hull affinities, and balance values live in shared JSON manifests.
- The current live loadout contract is `2 equipped + 2 consumable`; older three-artifact-slot ideas remain future design.

### The Authority Stack Is Productized Enough To Use

- The local stack has explicit modes, status, start/stop/restart commands, structured telemetry, and process identity checks.
- The control plane owns durable profile/session concerns.
- Sim instances own live gameplay truth and can idle/auto-stop when empty.
- Host promotion, live-session join behavior, and leave semantics are tested.

### The Test Harness Is A Real Safety Net

- `npm test` runs the core Three lane.
- `npm run test:fast` is the quick static/smoke gate.
- `npm run test:three` proves the Three renderer, infra smoke, and renderer fixtures.
- `npm run test:authority` proves the control plane, telemetry, remote authority, slingshot authority, inventory actions, hazards, death, joining, leaving, and host promotion.
- Visual fixtures generate inspectable screenshots rather than only boolean pass/fail output.

## Design Impact

v0.2 changes the center of gravity from "can the prototype do the cool thing?" to "which half-finished areas make the game feel whole?" The answer is no longer broad architecture. The next value is focused playability:

- tune movement and slingshot numbers;
- redesign maps around route chains;
- clarify HUD and ability presentation;
- finish meta-loop write-back and upgrade purchasing;
- migrate more renderer-owned presentation into Three;
- produce a public-facing build, website, and trailer-worthy capture plan.

## Known Limits

- Public hosted multiplayer is not shipped.
- Internet matchmaking is not shipped.
- Full procedural map generation is not shipped; current maps are authored/static with seeded content layers.
- The old renderer remains as a fallback lane while Three continues taking ownership.
- The visual fluid/ASCII chain still relies on legacy Composer passes.
- Some design-doc systems remain future-facing: megastructures, Scout Drifts, Doppler Echoes, signal flare, tether, full factions/missions, and deeper public progression.
