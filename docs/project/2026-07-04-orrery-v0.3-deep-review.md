## Stage 0 — Stop-The-Line (inside the live staircase work)

These are correctness holes directly under the staircase steps Codex is executing right now. They should land before more Ballpark consumers get wired.

### S0.1 `[ARCH]` SpatialIndex toroidal seam bug — reproduced, live, blocking

- **Where:** `scripts/sim/spatial-index.cjs:252-263` (`_axisCells`).
- **What:** Cell indices are wrapped modulo `count = ceil(worldScale/cellSize)`. When `cellSize` does not divide `worldScale`, the grid's implicit period is `count*cellSize > worldScale`, so queries spanning the seam wrap against the wrong period and **drop cells just past the seam**. Empirically reproduced: worldScale 10, cellSize 0.45 (deep-field × `large` profile's `flowFieldCellSize`) — body at wx=0.1, query at wx=9.9 r=0.35 → 0 hits. `medium` (5×5, 0.32) also non-divisible. Overload's `fieldCellScale` multipliers (1.12/1.28/1.5, `scripts/overload-state.cjs`) guarantee non-divisible sizes on every map under load.
- **Why:** `buildRelevanceView` already routes stars/wrecks/planetoids/scavengers through these queries, and as of `f3a0ae4` **wreck pickup candidates do too** — seam-adjacent entities can silently vanish from relevance and pickup near world edges. Every subsequent consequence-family migration inherits the bug.
- **Fix:** Snap in the constructor: `cellSize = worldScale / Math.round(worldScale / cellSize)` (keeps cells near requested size, makes the period exact). Decouple broadphase cell size from `flowFieldCellSize` (`ballpark-mirror.cjs:96`) — a flow-field tuning knob should not be a broadphase correctness parameter.
- **Verify:** Seam tests at non-divisible sizes (10/0.45, 5/0.32, plus an overload-scaled size) querying across the wrap in both axes; add to `test:sim-structure` and keep in `test:fast`. Re-run the nearest parity gate and ballpark-pickup after the fix.

### S0.2 `[ARCH]` Locale-sensitive query ordering

- **Where:** `scripts/sim/spatial-index.cjs:25` — tie-break via `String(a.id).localeCompare(String(b.id))`.
- **Why:** Roadmap acceptance says deterministic ordering; localeCompare is deterministic per-machine, not across machines/locales. Golden fixtures and replay depend on this.
- **Fix:** Codepoint comparison (`a < b ? -1 : …`).
- **Verify:** Existing determinism tests still pass; grep for other localeCompare in scripts/sim.

### S0.3 `[ARCH]` Mirror hygiene gates that exist but aren't enforced

- **Where:** `ballpark-mirror.cjs:54-60` (duplicate ids silently renamed `id#2`, recorded in stats), `lastRebuildMs` tracked but never asserted.
- **Fix:** In the sim-structure lane: assert `duplicateIds.length === 0` after a representative rebuild, and add a rebuild-cost budget assertion on a deep-field-scale fixture (pick the budget from measured baseline + headroom, and record the baseline in the test).
- **Why:** The roadmap's "catch duplicate bodies" goal is currently detected-but-never-enforced, and rebuild cost has no canary before the mirror becomes load-bearing.

### S0.4 `[GAME]` Authority-lane tests for the two uncovered consequence families

- **Where:** `tests/remote-authority.cjs` covers well death, pickup, pulse, slingshot, scavenger-death consequences, inhibitor — but **portal extraction (`player.escaped`) and star/planetoid push have no authoritative-snapshot test**.
- **Why:** Both are on the staircase's migration list. Migrating a family without a pre-existing behavior test means parity has nothing to be parity *with*.
- **Fix:** Add a portal-extraction case (spawn near portal, drive in, assert escape event + profile write-back) and a star/planetoid push case (spawn adjacent, assert velocity delta sign/magnitude band) before those families migrate.

### S0.5 `[GAME]` The remote input packaging path is still untested

- **Where:** `tests/remote-authority.cjs:355-363` posts `moveX: 1` by hand; `sendInput` packaging in `src/main.js:4208-4241` (unit-facing-vector + brake decoupling + pulse/consumeSlot latching) has no test.
- **Why:** This is the exact caveat MECHANICS-SIM-RENDER-AUDIT flagged; the brake fix that already shipped was in precisely this layer. Also feeds S1.9/S1.11.
- **Fix:** A CDP-driven or unit-extracted test that exercises `sendInput` composition: brake-without-thrust keeps a unit move vector; pulse latches across a dropped packet; slingshot hold state.

## Stage 1 — Authoritative Behavior Bugs

Fix these **before** the corresponding family's parity tests are written, so parity locks in corrected behavior rather than bug-for-bug compatibility. Most are small, high-yield server fixes.

### S1.1 `[GAME]` Scavenger→player contact is dead code — scavengers are zero-threat

- **Where:** `scripts/sim-runtime.cjs` — `applyScavengerBump` (~:2404-2414) reads `SCAVENGER_CONFIG.bumpRadius`/`.bumpForce`; `SCAVENGER_CONFIG` (~:174-186) defines **neither**. `dist < undefined` is always false. (Verified by hand at review time.)
- **Why:** In the packaged (remote-authority) product, scavengers physically phase through players. Combined with S1.13 (server scavengers also have no player-awareness AI), the threat layer of the extraction loop is absent in the real product.
- **Fix:** Add `bumpRadius: 0.04, bumpForce: 0.3` (client's values, `src/config.js`) to `SCAVENGER_CONFIG` — then playtest, because scavenger contact has never actually applied on the server and the values may need server-side tuning.
- **Verify:** Authority test: spawn scavenger on top of player path, assert player velocity perturbation in the next snapshots. This test should exist before the scavenger-contact family migrates to Ballpark queries.

### S1.2 `[GAME]` Breacher Burn toggles every tick while held

- **Where:** `sim-runtime.cjs` ability tick (~:4502-4508): `if (ability1 && !burnActive) on; else if (ability1 && burnActive) off;` with `lastInput` persisting across ticks.
- **Why:** One `ability1: true` packet flips burn on/off at tick rate until the next packet. Burn is effectively unusable remotely. Slingshot got `inputWasDown` edge detection; abilities didn't.
- **Fix:** Per-player `abilityWasDown` edge detection, same pattern as slingshot (~:4087-4096).
- **Verify:** Authority test: hold ability1 across 5 ticks → burn stays on; release → off.

### S1.3 `[GAME]` Resonant hull is dead on the server — **Greg decision**

- **Where:** eddies aged/expired (~:4572-4577) but never created (`harmonicPulse` spawns nothing); `tapAnchor` written (~:4584) with no gameplay consumer; `frequencyShift` sets `nextPulseInverted` (~:4592) which `applyPulse` never reads — and the guard latches the flag forever after first use. `player-brain.cjs:245-258` rig comments describe effects that don't exist.
- **Why:** A fifth of the hull roster is fiction; the hull-select screen sells abilities that do nothing.
- **Options:** (a) implement a minimal honest kit (harmonicPulse spawns one real eddy that applies a local current; frequencyShift actually inverts the next pulse; drop tapAnchor); (b) pull Resonant from the selectable manifest until the kit is real.
- **Recommendation:** (a) minimal-honest — the eddy concept is the hull's identity and a single working eddy is a small slice; but this changes what players can do, so Greg picks.

### S1.4 `[GAME]` Hauler Salvage Lock tags wrecks to no effect

- **Where:** `taggedWrecks` appended (~:4656), never consulted by pickup, scoring, or anything.
- **Fix:** Either wire the tag (e.g., tagged wrecks are reserved against AI/scavenger looting for N seconds, or grant a pickup-radius/value bonus) or remove the ability from the manifest. Smallest honest version: tagged wrecks are excluded from scavenger loot targeting — it's one filter in the scavenger loot scan.

### S1.5 `[GAME]` Star remnants and scavenger debris spawn with empty loot

- **Where:** star-consumption remnant `type: "vault", tier: 3, loot: []` (~:2256); scavenger death drop `loot: []` (~:3320); `tickPlayerPickups` marks empty wrecks `looted` on first graze (~:2586-2588).
- **Why:** The most dramatic emergent moment in the sim — a well eats a star and ejects a vault — pays out nothing. Player flies to the beacon, gets `looted`, gets nothing.
- **Fix:** Roll loot from the existing tier tables at creation (star remnant: tier-3 table; scavenger debris: fraction of what the scavenger had collected — the scavenger's cargo is already tracked).
- **Verify:** Authority test asserting non-empty loot on both spawn paths.

### S1.6 `[GAME]` Cosmic signatures are split-brain — client and server play different universes

- **Where:** remote start: client rolls a signature with **unseeded** `Math.random` (`src/main.js:2594`, vs the seeded local path :1691) and applies CONFIG overrides locally (run duration, well gravity, viscosity…). The server independently rolls a *seeded* `session.cosmicSignature` (`sim-runtime.cjs:162`) whose mods (`currentCouplingMult`, `wellGravityMult`, `signalGenMult`, `portalLifespanMult`, `sensorRangeMult` in signatures.data.json) have **zero server consumers** (grep-verified).
- **Why:** In remote play the client *believes* one modifier set (and shows its name/flavor in the briefing), the server plays vanilla, and two clients can believe different universes. Signature identity — a store-page feature bullet — is currently HUD fiction in the packaged game.
- **Fix:** Server-authoritative: server rolls seeded, applies its own mods in the tick path (coupling/gravity/signal/portal-lifespan multipliers are all single multiply sites), and ships `signature` in the session snapshot; the client applies *presentation* only from that. Delete the client's remote-path roll.
- **Verify:** Authority test with a forced signature seed asserting a mod actually changes server behavior (e.g., portal lifespan); client briefing shows the server's signature name.

### S1.7 `[GAME]` AI players thrust at intensity²

- **Where:** `sim-runtime.cjs` ~:4418-4420 — AI sets `lastInput.moveX = cos(angle) * thrustIntensity` **and** `thrust = thrustIntensity`; the shared physics path multiplies them. Ghost's 0.15 cruise becomes 2.25% effective accel.
- **Why:** AI rivals are drastically weaker than their personality tables intend — "AI rivals share the run" is a pillar-adjacent feature bullet.
- **Fix:** Unit move vector for AI (`moveX = cos(angle)`), intensity only in `thrust`.
- **Verify:** Existing AI-behavior expectations; a fixture asserting AI cruise speed lands near its personality target.

### S1.8 `[GAME]` Signal keys on requested thrust, not delivered thrust

- **Where:** `tickPlayerSignal` (~:3510) gates on `input.thrust > 0.1`.
- **Why:** An empty-tank player holding the trigger radiates full thrust signal (and forfeits decay) while stationary. Signal Is Consequence should tax *output*, not *intent*.
- **Fix:** Gate on the delivered thrust intensity after the delta-v gate (the movement step already computes it — expose it on the player for the signal tick).

### S1.9 `[GAME]` Slingshot tap can be dropped remotely (latch asymmetry)

- **Where:** `pulse`/`consumeSlot` latch client-side until acked; `slingshot` is instantaneous held state (`src/main.js:4225`). A tap between two in-flight input POSTs never reaches the server.
- **Fix:** Latch slingshot edges like pulse (send engage/release edges, or hold-latched until acked). Cover in the S0.5 packaging test.

### S1.10 `[GAME]` Shield/grace early-return straddles overlapping wells

- **Where:** `applyWellGravity` (~:2458-2482) — shield/hull-grace consumption early-returns, skipping gravity *and kill checks for all remaining wells* that tick.
- **Fix:** Consume the shield against the well that triggered it, continue evaluating remaining wells (or at minimum continue their gravity).

### S1.11 `[GAME]` Server never normalizes the move vector

- **Where:** `scripts/sim-protocol.cjs:17-38` clamps `moveX/moveY` each to [-1,1] independently — a crafted (1,1) is magnitude √2 → ~41% free thrust.
- **Fix:** Normalize (or clamp magnitude to 1) server-side in `normalizeInputMessage`.
- **Why:** Trivial now, correctness-of-authority later; also the kind of thing the golden fixtures should encode.

### S1.12 `[UI→GAME hazard]` Map-select "reroll" prompt is wired to host-reset

- **Where:** reroll is keyboard-only (`inputManager._keys['KeyS']`, `main.js:4031`); the on-screen hint says "Y reroll" (:6057) per `BUTTON_LABELS.reroll` (`input-prompts.js:17`), but controller Y (button 3) is `deletePressed` → **host reset in remote mode** (:4049-4063). `BUTTON_LABELS.reroll` and `.delete` both claim Y.
- **Why:** Controller players cannot reroll; pressing the *advertised* button can reset a live multiplayer session. Worst controller finding in the review.
- **Fix:** Give reroll a real controller binding (X is free on that screen), fix the label table conflict, move host-reset behind a hold-to-confirm.
- **Verify:** Controller-path test on map select; hint text matches actual binding (assert from `BUTTON_LABELS`, not a string literal).

### S1.13 `[GAME]` Server scavengers are a different species from client scavengers — flag, then converge

- **Where:** client `src/scavengers.js` has fluid coupling, flee hysteresis, loot pause, vulture player-tracking/pulse, spawn stagger; server (~:3360-3465) has flee/loot/extract/drift only — no signal reaction (despite the :3484 comment claiming signal "escalates scavenger behavior"), no player awareness.
- **Why:** Combined with S1.1 this is why remote runs feel threatless. This is bigger than a bug fix — it's the "scavenger contact" family's real scope.
- **Fix (staged):** land S1.1 first; then port the client's vulture/flee behaviors server-side as part of (or immediately after) the scavenger-contact family migration, with signal-reaction wired to the existing per-player signal (see S5.4). Client scavenger AI then becomes dead code to retire with the legacy renderer (S4.12).

## Stage 2 — Shared Movement Truth

The golden fixtures (`8f1ca56`) locked the server's movement math. Now make the *constants and kernels* single-sourced so client and server can't drift again. This is the "movement is the game, so it gets a harder gate" principle applied to code shape.

### S2.1 `[ARCH]` One physics kernel, four copies

- **Where:** `inversePowerForce` / `orbitalCurrentSpeed` / `proximityForce` / `waveBandForce` exist verbatim in `src/physics.js:43-160`, `sim-runtime.cjs:514-560`, `scripts/coarse-flow-field.cjs:24-37` (client flow-field re-imports the src copy). Currently line-identical *by discipline only*.
- **Fix:** The content-data pattern already proved the shape: extract to a shared module consumed by both sides (a `.cjs` core with an ESM re-export shim, mirroring how `*.data.json` is shared). Add a parity test that imports both entry points and compares outputs on a fixture grid so any future fork fails loudly.
- **Verify:** Golden fixtures unchanged; physics.cjs parity suite green.

### S2.2 `[GAME]` Thrust constant: client 1.7 vs server 2.5 — **Greg decision on which feel is canonical**

- **Where:** `src/config.js:37` (`thrustAccel: 1.7`) vs `scripts/sim/player-movement-step.cjs:66,91` (hardcoded `2.5`). Local play accelerates 32% slower than packaged play with identical hulls.
- **Why:** Every local playtest and every tuning session on the local path evaluates a different game than the product. The dev panel tunes a constant the packaged game ignores.
- **Recommendation:** The server number is canonical — it's what the Deck build plays and what the golden fixtures now encode. Move it into shared config data (S2.3's table), make the client consume it, and retune local feel only if a fresh playtest says 2.5 feels wrong.
- **Verify:** Local-vs-remote side-by-side drive test; golden fixtures updated intentionally (not accidentally) if the number changes.

### S2.3 `[ARCH]` Retire the hand-copied `SERVER_*` constant tables

- **Where:** `sim-runtime.cjs` ~:187-231 (`SERVER_INPUT/SERVER_WELLS/STAR_SERVER/PLANETOID_SERVER/WAVE_SERVER/SLINGSHOT_SERVER/SERVER_COMBAT`) plus `PORTAL_CONFIG.waves` duplicating `CONFIG.portals.waves` verbatim.
- **Why:** These are a parallel constants universe hand-synced against `src/config.js`. The thrustAccel drift (S2.2) is exactly how this fails. Hulls/items/balance/session-profiles already got the shared-JSON treatment; movement constants did not.
- **Fix:** `movement.data.json` (or extend balance data) consumed by both config.js and the runtime. Migrate table-by-table with golden fixtures green after each.

### S2.4 `[GAME]` Wave-ring decay is tick-rate-dependent; wave push varies ~4× by map profile

- **Where:** `amplitude *= 0.97` per update on both sides (`src/wave-rings.js:38`, `sim-runtime.cjs:~2192`) — but client fixed-steps at 30 Hz and server `waveTickHz` is 15/12/10 by profile, so rings last 2–3× longer on the server, longer still on large maps. Separately, medium/large maps deliver wave push through the coarse field scaled by `waveShipPush * fieldFlowScale` (0.8 × 0.22/0.28) at 4–6 Hz rebuild — ~4× weaker and heavily quantized vs small maps' direct band force.
- **Fix:** dt-correct the decay (`amplitude *= Math.pow(0.97, dt * REF_HZ)` — drag already got this treatment). For the coarse-field magnitude split: either normalize the scale so the same wave means the same push on every map, or write the intended difference into DESIGN.md — right now it's an accident of the scaling work, not a decision.
- **Verify:** Fixture: identical ring, three profiles, assert equal integrated impulse within tolerance (or the documented intended ratios).

### S2.5 `[GAME]` Local slingshot diverges from authoritative slingshot

- **Where:** client cancel profile applies `CONFIG.wells.*` pull to **all** anchor types (`src/slingshot.js:275-281`) — for stars/planetoids it cancels a force that doesn't exist; release direction is facing (client :307-308) vs input-move-with-velocity-fallback (server ~:3995-4001).
- **Fix:** Port the server's per-anchor-type pull profile and release-direction rule to `src/slingshot.js` — or, cleaner: since the slingshot is server-authoritative in the product, fold local-mode slingshot onto the shared kernel from S2.1 so there is only one implementation. Recommend the latter as part of the movement-step consolidation.

### S2.6 `[ARCH]` Toroidal math: five copies and a semantic trap

- **Where:** wrap/displacement/distance in `sim-runtime.cjs:481-513`, `spatial-index.cjs:10-20`, `body-registry.cjs:7`, `coarse-flow-field.cjs:6-13`, `src/coords.js:202-244`, plus `worldDisplacementClamped` (~:1932) as a fifth variant. **Trap:** `wrapWorld(v)` in coords.js wraps a *position*; `wrapWorld(value, worldScale)` in sim-runtime wraps a *delta* — same name, opposite jobs.
- **Fix:** Shared toroidal module (same shape as S2.1); rename one of the `wrapWorld`s during extraction (`wrapDelta` vs `wrapPosition`). Also fold the already-drifted seeded-generation copies (scripts copy has `applyWellVariance()`, src mirror doesn't) and the code-identical rng-stream / flow-sample pairs into the same shared-source treatment.

### S2.7 `[GAME]` Per-mechanic semantic convergence list

Smaller divergences to fold in while the relevant family migrates, each a one-decision item:

- **Star push ignores star type on the server** (~:2380 mass-only vs client `typeDef.pushMult`, `src/stars.js:224`) — port type multipliers server-side (star/planetoid push family).
- **Mid-burn regen:** client regens ambient delta-v while burning (`ship.js:224-231`, config comment says "always-on"); server returns before regen when burning (~:4690-4694). Pick one — recommend server semantics (burn commitment is the delta-v economy's teeth) and fix the client + config comment.
- **Wreck drift:** client 0.08-strength wellPull profile (`wrecks.js:116-139`) vs server bespoke `0.0045*mass/dist^1.5` + swarm shear (~:2283-2335). Converge on the server curve in the shared kernel.
- **Well grace:** server `brain.wellGraceDuration` + shields + hauler survive (~:2457-2505) vs client profile-rank grace + free pass (`main.js:4416-4443`). Two unrelated forgiveness systems; keep the server one, make local mode consume it via brain.
- **Surf normalization:** server `/2.5` (~:3799) vs client `/0.7` (`src/sim/flow-field.js:63`) — the surf channel means different things per side; unify in the FlowSample contract.
- **Pulse recoil:** client `pulseRecoil: false` (config.js:386) vs server always-recoil (~:2718-2719). Pick one (recommend recoil-on everywhere; it's a movement-consequence).

## Stage 3 — Snapshot/Event Productization Adjuncts (staircase step 4)

The scaffolds (`sim-event-journal.cjs`, `sim-snapshot-ring.cjs`) are good code with zero production wiring (grep-verified: only tests import them). Step 4 is mostly re-plumbing, plus the following specifics the scaffolds alone won't catch.

### S3.1 `[ARCH]` Wire the journal behind `publishEvent`

- **Where:** `publishEvent` (`sim-runtime.cjs:976-988`): seq + type + simTime, **no tick, no runId, no lane**, 128-cap `shift()` array. 54 call sites, 36 event types — the taxonomy already exists.
- **Fix:** Swap the ring for `SimEventJournal` inside `publishEvent` (one seam), stamping tick/runId/lane. Lane defaults can start coarse (`global` for everything, `debug` for stats) and refine per-family. Perf note first: the journal's per-append `JSON.parse(JSON.stringify())` clone (journal:10-14) and the ring's double-clone on append (ring:86) need a cheaper structured-clone or shallow-freeze policy before sitting in the 15 Hz tick path.

### S3.2 `[ARCH]` Event-seq reset hazard is live today

- **Where:** `startSession` resets `recentEvents=[]`, `nextEventSeq=1` (~:1330-1331); `/events?since=` (~:5599-5607) has no reset signaling. A client holding a stale `since` across a session restart silently misses events 1..since of the new run.
- **Fix:** RunId-stamped events + the already-written `EventPlaybackGate` on the client. This is precisely the scaffold's reset taxonomy; wiring S3.1 closes it — add the client gate at the same time and a test that restarts a session under a polling client.

### S3.3 `[ARCH]` Snapshot discipline: stop shipping the live world by reference

- **Where:** `snapshotBody()` (~:1425-1533) serializes the **live internal arrays** (`wells/stars/wrecks/planetoids/portals/scavengers/fauna/sentries`) — internal representation *is* the wire format (wreck loot internals, scavenger AI state leak); no `snapshotId/runId/serverTime/lastEventSeq/schemaVersion`; `recentEvents.slice(-32)` rides every snapshot; **dead/looted wrecks are never pruned** so `mapState.wrecks` and every snapshot grow monotonically over a run.
- **Fix (ordered):** (1) prune-or-tombstone dead wrecks with a retention rule — this is a live memory/wire leak; (2) add the envelope fields (the roadmap-D list); (3) introduce a projection layer (explicit per-category field lists) so internals stop leaking — this is also the natural place `RenderableHint` gets attached for S4.1; (4) lanes/relevance-filtered snapshots last, per roadmap "full snapshots first, journal second, deltas third."
