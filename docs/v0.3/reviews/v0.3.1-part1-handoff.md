## Completion Contract (applies to every item)

Every executing agent, on finishing (or abandoning) an item, writes a
completion MD to `docs/v0.3/reviews/completions/<item-id>-<slug>.md`
containing:

1. **Outcome** — done / partial / blocked, in one line.
2. **What changed** — files touched, behavior deltas, in plain language.
3. **Evidence** — how you proved it (tests run, captures, probe output);
   claims without evidence will be bounced.
4. **Deviations** — anywhere you departed from the design docs, and why.
5. **Open questions** — decisions you discovered that belong to Greg.
6. **Anchor updates** — any doc references that drifted while you worked.

Orrery reads and reviews every completion MD as they land. Write for a
reviewer who has the design docs open but was not watching you work.

## Work Items

### W1-A — One movement truth

**Goal:** the game has exactly one movement model. Canonical thrust is the
server's 2.5, stick-relative; the client conforms (no 1.7, no
facing-relative thrust, no divergent brake). One gravity formula family
parameterized per body class replaces the three current families. Dead
movement knobs (Resonant eddyStrength, Drifter slipStream,
AI_PLAYER_CONFIG.thrustAccel/drag) are implemented or deleted — none may
remain as decorative config.
**Read first:** review doc S5; `v0.3.1-velocity-ledger.md` §A/F/G.
**Done when:** a single shared movement/constants source is consumed by
both client and authority; a test proves local and authoritative
trajectories match for identical inputs on a fixture; the velocity ledger's
§F divergence table is empty or every remaining row is intentional and
documented.

### W1-B — One sea (fabric convergence)

**Goal:** there is one flow truth. The authoritative field carries well
terms + live event waves (dt-correct per-second decay, uniform weight
across maps — the fieldFlowScale divergence dies). The GPU fluid becomes a
presentation of that field: forced by it each tick, free to add detail
below the ambient floor, never contradicting it (no painted infall where
truth is tangential). Execute the keep/kill/redesign table in
`v0.3.1-fabric-design.md`. RULE (Greg, 2026-07-14): any effect whose call
is unratified or marked as a Greg decision (e.g. planetoid wake) is
**shrunk to zero or disabled entirely** — not decided by the executor —
until a later design pass steps through it. Disabled ≠ deleted: keep the
lever, note it in the completion MD.
**Read first:** `v0.3.1-fabric-design.md` (all); review doc S8/S8a.
**Done when:** the doc's fabric-v2 tests pass, including the defining one:
disabling the GPU sim changes nothing about gameplay outcomes; and a
direction-agreement check between rendered fabric motion and authoritative
flow passes above the ambient floor.

### W1-C — Seeded sea + determinism guardrails

**Goal:** every match's fabric starts from a seeded sea state — swell
trains generated from the map's procgen history — same seed, same sea; new
match, new sea. All sim randomness routes through the seeded RNG streams.
**Read first:** review doc S8 (seeded sea + non-negotiable rider);
`rng-stream.cjs`.
**Done when:** two runs from one seed produce identical sim state hashes
over N ticks (replay-checksum test, committed and in a test lane); a
guard exists that fails when bare `Math.random` enters the sim path (live
fallbacks exist today — find and fix them); two different seeds produce
visibly different spawn seas in captures.

### W1-D — Slingshot v2

**Goal:** slingshot feels like a grappling hook under exactly five knobs —
captureRadius, magnetism, coyoteTime, payoffCurve, chainWindow — with the
S4 units/steps/starting-biases. Release is cap-relative: no
teleport-to-max. Release direction must be coherent with stick-relative
thrust (verify no facing-vs-velocity artifacts). Full telegraph chain: aim
cue → lock → arc → release ghost.
**Read first:** review doc S4 + S5 (G4); `v0.3.1-velocity-ledger.md` §A
rows 10-12.
**Done when:** S4's test passes — a slingshot route beats thrust-only by
**25% route time** (ratified) on a fixture using only the five knobs; captures show the
telegraph chain; the release Δv is provably bounded by the payoff curve.

### W1-E — Units doctrine + ruler layer

**Goal:** spatial tunables read in meters that draw on screen. One
conversion module (sim units → meters → screen px) beside coords.js; a
toggleable debug overlay renders every contract tunable at true scale with
labels (scale bar, radii rings, vector pairs, temporal windows); dev-panel
sliders snap to declared steps; a per-tick force ledger decomposes ship Δv
into labeled vectors. Every tunable in the S4/S5 contracts registers a
draw handler — an undrawable tunable is a review failure by doctrine.
**Read first:** review doc S4 (units doctrine, step rules, ruler layer,
force ledger).
**Done when:** captures show the overlay on a live run with slingshot and
movement contracts fully drawn; changing a slider moves its geometry the
same frame; steps snap.

### W1-F — The Conductor (sim-controller timer module)

**Goal:** one seeded, match-scoped timing module inside the server sim
controller, beside the other clock/math processes. Four generic
primitives: threshold fields (any spawner declares "after X minutes"),
severity waves (scheduled spawn-wave primitive: cadence, budget, tier
table — large/dangerous entities may ONLY arrive via an announced wave),
interval lerps (registered intensities interpolate between two scheduled
events), and an offset guard (no two registered timers fire within the
guard window). Inhibitor phases (start zero, grace, three even phases)
and wormhole/portal open-close windows are the first two clients,
offset by construction. The legacy pressure integrator and its HUD meter
are deleted. Match modifiers multiply Conductor values pre-generation.
**Read first:** review doc S12; S9 (epochs as a future client).
**Done when:** the schedule is bit-reproducible from seed; an invariant
test fails on any big-entity spawn outside a wave and on any two events
inside the offset guard; phase transitions publish world events; the
pressure variable and meter are gone from sim, snapshot, and HUD.

### W2-A — Anomaly catalog schema + collapse epochs

**Goal:** wells become an anomaly catalog. Implement the schema (fabric
signature, interaction verb, tell, growth behavior, tunables contract) as
data + code structure, migrate current wells onto it as the first
entries, and implement per-entity growth with visible tells plus banded
collapse epochs that retune the sea. No time dilation; nothing per-player.
Shipping trio is ratified: **supermassive + micro black hole + pulsar**,
after base-well parity is proven. Shallows keeps a fixed curated cast
(teaching overture); Expanse/Deep Field use true seeded draws. Signatures
must be parameter vectors over existing field machinery — bespoke physics
means the entry is not catalog-ready.
**Read first:** review doc S9 (incl. rulings), S8 (retune hooks).
**Done when:** two seeds draw different anomaly casts; a consumed star
visibly grows the specific well that ate it; HUD-less screenshots at
epochs are orderable by a fresh reviewer; the catalog schema doc exists as
the canonical spec per the S6 policy.

### X-A — Config red-flag audit

**Goal:** no unfeelable knobs. Sweep sim/client config for sub-0.01
constants and re-express them in perceivable units per the step-change
rules (e.g. pressureFromTime 0.0005/s → time-to-threshold minutes; wreck
gravity 0.0045 → re-unitized). Every surviving tunable gets a declared
unit, range, step, and start bias, or gets deleted. Flag (do not change)
the per-player timeSlow ×0.3 mechanic for Greg review — ruling on record:
never per-player time.
**Read first:** review doc Red Flags Ledger + step-change rules;
`v0.3.1-velocity-ledger.md`.
**Done when:** an audit table (constant → old form → new form → owner
system) is committed; renames/reunitizations land with tests proving
unchanged behavior at equivalent values.
