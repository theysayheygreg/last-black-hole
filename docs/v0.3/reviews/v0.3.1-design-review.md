## S4 — Slingshot v2 Goal (locked) + Debug Handler Design

### Slingshot v2 goal

**Feel target.** Thematic: my ship can dive at a gravity well, commit to the
arc, and steal momentum from the dying star — leaving faster than I arrived,
because physics still works at the end of the universe. Reference:
Spider-Man's swing — attach is generous and clearly shown, the game owns the
arc while I own the timing, release direction is my skill expression under
rules learned in one encounter. (Reference-research step: also pull Just
Cause grapple and Outer Wilds gravity assist before locking.)

**Tunables (5), with starting bias.** Conflicting assists get staggered
starts so effects are attributable one at a time. Some may sit at 0/disabled
— the lever exists even if unused.

| Tunable | Unit | Start bias | Step (one felt difference) |
|---|---|---|---|
| `captureRadius` | meters, drawn on screen | medium | 25 m (~2 hull lengths) |
| `magnetism` | max entry-bend, degrees | **large** — overshoot, dial back | 5° |
| `coyoteTime` | ms | **small** | 50 ms (3 frames @60) |
| `payoffCurve` | exit speed ÷ entry speed per quarter-turn | medium | 0.1× |
| `chainWindow` | seconds | may start 0/disabled | 0.5 s |

**Test.** Fixture map: agent using only these five knobs makes a slingshot
route beat thrust-only by a target margin; capture shows the telegraph chain
(aim cue → lock → arc → release ghost); a first-time player can state the
rules after three swings.

### Units doctrine (GREG, applies to every system)

Tuning values must converge on human-readable, **screen-readable** units — a
value translates to x meters on screen.

- Canonical spatial unit: the **meter**, pegged in fiction to hull length
  (e.g. Drifter = 12 m — exact peg is a Greg call). No normalized 0–1
  spatial fractions in tunable contracts.
- One conversion pipeline: sim units → meters → screen px, in a single
  module beside `coords.js` (same no-inline-conversion rule).
- Spatial tunables carry units in name or schema: `captureRadius_m`.

### Step-change rules (GREG, applies to every tunable)

Every tunable declares a **step**: the smallest increment that produces a
felt difference. "Must move the knob this much to see an effect" becomes
part of the contract, not tribal knowledge. Design rules, not code yet:

- A tunable's contract line is: `name, unit, range [min–max], step, start
  bias`. If you can't state the step, you don't understand the knob yet —
  that's a finding, not a formality.
- Tuning moves in whole steps. Sub-step changes are banned in tuning
  sessions: they produce false convergence and untrackable feel drift.
- Perceptual floors for steps by kind:
  - **spatial** — no step smaller than ~half a hull length or ~1% of screen
    width, whichever is larger at gameplay zoom;
  - **temporal** — no step smaller than 2–3 frames at 60 fps (~33–50 ms);
  - **multipliers** — no step smaller than 5% of current value.
- A knob whose honest step is below its floor is mis-unitized or fake —
  route it to the Red Flags Ledger (this is the 0.000x rule's second half:
  0.0005 isn't just unreadable, it has no legal step).
- Dev-panel sliders snap to steps; the ruler layer labels values in steps
  ("capture 450 m · step 25 m") so a session's change history is countable.

### Debug handler design — "the ruler layer"

Toggleable dev overlay rendering every contract tunable on the live game:

- **Scale bar** — always-on ruler showing 100 m at current zoom.
- `captureRadius` — true-scale ring per well, labeled ("450 m").
- `magnetism` — deflection vectors along the approach path; label max bend.
- `coyoteTime` — ring lingers ghosted after exit, fade = window remaining.
- `payoffCurve` — entry vs projected exit vector pair at release point.
- `chainWindow` — countdown arc toward the next eligible well.

**Handler contract (the enforcement):** every tunable in a system contract
MUST register a draw handler — spatial → true-scale geometry + meter label;
temporal → visible window/decay; multiplier → before/after vector pair. A
tunable that cannot be drawn cannot be felt and fails review. This is the
0.000x red flag turned into policy. Live readout panel: value in human
units beside each slider; slider moves → geometry moves same frame.

## S5 — Movement Velocity Ledger + Strength Priority (draft, awaiting Greg)

Full force inventory: `v0.3.1-velocity-ledger.md` (same folder). Headlines:

1. **Two games exist.** Client sim: thrust 1.7 along *facing*, currents from
   the GPU fluid (wakes, turbulence). Authoritative sim: thrust 2.5 along
   *stick*, currents from analytic well-orbit flow only. All local feel
   verdicts to date were made against the non-shipping game.
2. **Open fabric is a vacuum on the server.** Away from wells: thrust + drag
   only. The sea exists only in well corridors.
3. **Slingshot release ≈ set-speed-to-cap** (Δv ~12.6 vs cap 8.0 after a 1 s
   hold). Not a payoff curve — a binary teleport. Explains "not usable, not
   a grappling hook."
4. **Waves are a different mechanic per map by accident**: push ~40% of
   thrust on Shallows vs ~10% on Expanse/Deep (`fieldFlowScale`), and
   per-tick decay yields three wave lifetimes (client 0.4 s / Shallows 1.5 s
   / Deep Field 2.3 s half-life).
5. **Near wells the intended hierarchy already works**: coupling current
   (≤2.6× thrust) > gravity (≈1× Drifter thrust) > thrust. Escape is a real
   coupling/thrust fight. The ladder exists in one regime only.
6. **Dead/fake knobs:** Resonant `eddyStrength`, Drifter `slipStream`,
   `AI_PLAYER_CONFIG.thrustAccel/drag` (AI players actually share the player
   movement step — systems-peer already true in code). → Red Flags Ledger.
7. Three gravity formula families (player/scavenger/wreck), none shared.

### Target strength priority ladder (weights as % of base thrust)

| Rung | Regime | Rule | Target weight |
|---|---|---|---|
| 1 | Well corridor | Sea beats thrust; escape = angle + timing, not throttle | coupling 150–250%, gravity 60–120% |
| 2 | Open fabric | Thrust wins; sea modulates, never steers | ambient fabric ≤30% |
| 3 | Waves | Modulation you can surf; can't stall or capture | 30–50% at peak, uniform across maps |
| 4 | Entity impulses | Moments, not forces; always attributable | ≤20% of terminal speed per hit; slingshot is the deliberate exception via `payoffCurve` |
| 5 | Drag | The referee; sets settle time | equilibrium at terminal in ~2 s |

### Convergence requirements (design, for Codex staging)

- One movement truth: client adopts the authoritative movement step (or the
  shared-constants module), one thrust value, one thrust direction rule.
- One gravity formula family parameterized per body class.
- dt-correct wave decay (per-second, not per-tick/frame); wave weight
  becomes an explicit per-map *identity* choice or is unified — not an
  accident of `fieldFlowScale`.
- Open-fabric ambient sea: decide whether the server fabric gets a real
  ambient current/turbulence term (rung 2's ≤30%) so surfing exists between
  wells.
- Delete or implement dead knobs; wreck gravity 0.0045 re-unitized.

### Force ledger (ruler-layer extension)

Debug overlay decomposes this tick's Δv on the ship into stacked labeled
vectors — thrust, coupling, gravity, wave, impulse, drag — in meters/s².
"Why did my ship do that" becomes answerable by looking. Every ladder rung
must be visible as its own vector class.

## S8 — Waves/Surfing v2 Goal (in progress)

**Greg calls (2026-07-14):**

- **Split the difference, slightly.** The fabric at map spawn is not
  completely static — there is a seeded initial sea state, with a designed
  **sim reason** for it (in-fiction cause), generated from the map's
  procgen. After spawn, entity effects alone keep the sea unique and
  moving. No continuous ambient wave generator.
- **Revisit every individual fabric effect** — suspicion confirmed by
  inventory: LBH has **three seas** (GPU fabric = 100% cosmetic, nothing
  reads it back; client analytic FlowField drives solo; server flow drives
  MP), with visible contradictions (fabric paints infall at wells, the
  authoritative current is pure tangential). Effect-by-effect
  keep/kill/redesign calls + the one-sea v2 architecture live in
  `v0.3.1-fabric-design.md`. Definition-of-done test: disable the GPU sim
  → gameplay outcomes unchanged.
- **Wave Race 64 confirmed as the reference.** Its actual physics are
  documented online — research pass running to pull representation, rider
  forces, and readability techniques into this design.

**Fabric truth contract (GREG, 2026-07-14):** the fabric results must feed
back into the visual ASCII shader — the high-res visual sim must match the
lower-res Ballpark physics. Principle: one flow truth, two resolutions.
The authoritative (coarse) flow is the source; the GPU fluid is a high-res
*presentation* of it — server flow drives/forces the visual sim, and visual
detail (turbulence, wakes) may decorate but never contradict. Rule with
teeth: **nothing on screen may promise a force the authority won't
deliver** — if the ASCII fabric shows a current, coupling honors it; if the
sim carries a wave, the shader shows it. This kills the current split
(client coupling reads GPU fluid; server reads analytic flow — two
different seas).

**Feel target (draft).** Thematic: waves are moving terrain — swells in the
fabric I see coming, position for, and ride for free speed; caught
wrong-footed they shove me off my line. Reference: Wave Race 64 — swells
physical, readable at distance, rhythm learned in minutes.

**Wave Race 64 research findings (2026-07-14, source-confirmed via MVG /
DF Retro / decomp / speedrun tutorials):**

- Waves are **authored events, not a fluid sim**: parametric wave trains
  from fixed world generators on timers + one camera-anchored ambient sine
  ripple; simulated only in a bubble around the player. Structurally
  matches our seeded-sea + event-waves plan and coarse-authority/local-
  presentation split.
- **One surface function drives rendering, collision, buoyancy, and AI** —
  what you see is exactly what you feel. The fabric truth contract, proven
  in 1996. (Their one fake: craft don't deform the water.)
- **Core skill is a single rule: hull angle vs wave face at contact.**
  Parallel = momentum forward, free speed; perpendicular = momentum
  converts downward, plunge (itself a usable move); everything else falls
  out. LBH mapping: **ship-velocity angle vs wave front** as the one
  interaction — with = boost, against = cost, across = line drift.
- **Scripted-but-physical**: timer-authored waves are learnable terrain
  (speedrunners "miss the cycle"); physics on top gives expressive skill.
- **Conditions evolve within a race** (tide drops per lap, rerouting the
  course). LBH mapping: **collapse retunes the sea over a run** — wells
  consuming mass change the swell; the clock becomes readable in the
  water. Direct feed into the Wells/collapse pass.
- Free telegraphing: props bob on the same surface — wrecks/fauna should
  ride the fabric so incoming swell is read off them before it arrives.
- Vertical excursion is a pure speed tax (flat-riding fastest; measured
  ~122 bobbing vs ~127–128 held flat) — analog: staying coupled to the
  fabric beats fighting it, and the tax is a tunable.

Sources: MVG youtube.com/watch?v=zS146vQYflw · DF Retro
youtube.com/watch?v=V4MMlKhJfGI · decomp github.com/LLONSIT/Wave-Race-64
(`water_69D0.c`: 384×128 s16 triangular heightfield, 64 u/cell) · WR64
speedrun tutorials (controls/advanced/dive).

**Candidate sim reason for the seeded sea (to react to):** the map's sea
state is the *residue of its history* — procgen seeds swell trains
radiating from the region's past collapses (well positions/masses generate
the initial interference pattern). The sea you spawn into is the memory of
what died here; every wave after that is something happening now. Keeps
Signal-Is-Consequence clean: ambient sea = past events, live waves =
present events.

**Tunables (draft, 5):** `wavePush` (% base thrust, step 5%), `waveWidth`
(m, step 25), `waveSpeed` (m/s, step 10%), `waveLifetime` (s half-life,
dt-correct, step 0.5 — replaces per-tick 0.97), `crestTell` (s visible
before arrival at gameplay zoom, step 0.5). Seeded sea gets its own small
set once the fabric-effect audit lands.

**Test (draft).** Wave-riding agent beats wave-ignoring agent by target
margin; crossing against costs visibly; crest readable `crestTell` s out
with HUD hidden; two maps with different procgen seeds produce visibly
different spawn seas.

## S9 — Wells → Anomaly Catalog (redesign, GREG direction)

**Greg (2026-07-14):** wells today are static, growth is not telegraphed,
and tuning a few variables is a half measure — wells are always dangerous
but have **no character**. Map and fabric currently express only well
*sizes and distances*. Redesign wells into a verbose feature: **an anomaly
catalog** — micro black holes, supermassive holes, pulsars, quasars, etc.
Every generated map **selects from a list of potential anomalies that are
about to devour the universe**. (This is the catalog principle applied to
terrain: design catalogs seeds draw from, not fixed ecosystems.)

**Visual/thematic targets:** Outer Wilds (thematic — read the world's age
in the sky) + **Interstellar (visual** — Gargantua: accretion disk,
lensing band, doppler asymmetry: approaching side burns brighter).

**Catalog schema — every anomaly defines:**
1. **Fabric signature** — what it does to the sea (currents, swell trains,
   dead zones); the map IS readable because each signature is distinct.
2. **Interaction verb** — what skilled play does with it (slingshot, ride,
   time, avoid, harvest).
3. **Tell** — how it telegraphs state and growth (per-entity: the well
   that ate a star is visibly THAT well).
4. **Growth/collapse behavior** — how it participates in devouring the map.
5. **Tunables contract** — its own knobs with units/steps, on the shared
   base (killRadius m, gravity reach m, current strength % thrust).

**Starter catalog (draft for Greg to cut/extend):**

| Anomaly | Fabric signature | Verb | Signature danger |
|---|---|---|---|
| Micro black hole | tight fast vortex, tiny reach | precision slingshot, chains | small kill edge, high gradient — punishes sloppy lines |
| Supermassive | vast slow spiral, map anchor | commit long orbits; **time dilation** near horizon (sim already has per-player timeSlow ×0.3 — assign it here, Interstellar-honest) | inevitability; consumes the endgame |
| Pulsar | periodic directional swell trains on a fixed timer | ride the beat — the map's metronome (Wave Race generator, literally) | beam sweep window; learnable cycle |
| Quasar | permanent jet — a directional current highway + radiation lane | fast travel along the jet | signal/heat cost while riding |
| Binary pair | oscillating interference currents between two orbiting wells | chain slingshots, thread the weave | lanes open and close on the orbit period |
| Magnetar (candidate) | local signal distortion zone | hide/ambush (rivals' sensors scramble too) | your own readouts corrupt inside |

**Procgen rule:** each map draws N anomalies from the catalog (seeded) —
"which anomalies are devouring this universe" becomes the run's identity
and the Run-It-Twice variety engine. Sizes/distances remain, but as
*placement* of characters, not the whole vocabulary.

**Collapse integration (from Q9 draft, still stands):** per-entity growth,
banded epochs, sea retune per epoch, HUD-less orderable screenshots,
endgame ownership question (Greg lean pending — portals guttering vs
Vessel's hour vs final merge).

**Creative direction (ratified 2026-07-14):** the catalog is a **cast,
not a bestiary**. Every map is a solar system in its last hour; anomalies
are what its bodies are becoming — a pulsar is a star still screaming, a
micro hole is a star already gone, the supermassive is where everything
ends. Admission rule: an anomaly earns a slot only if it is a
recognizable *stage of the universe's death*, never a differently-shaped
hazard. **Shipping trio ratified: supermassive + micro + pulsar**
(terminus, sharpness, rhythm — complete emotional range in three).
Shallows is the overture: fixed curated cast, seeded variance only;
Expanse/Deep Field get true seeded draws. Casting stays a Greg/design-pass
act; W2-A builds the stage.

- **No time dilation now; never per-player.** The supermassive dilation

### S9a — Side sketch: The Singularity (singular supermassive minimum)

Separate exploration, not current work. Every generated map guarantees
**exactly one supermassive** — THE anomaly devouring this universe, the
game's title made literal. Procgen varies its satellites (micro holes,
pulsars, etc.), never its existence.

- The one entity that gets the full Interstellar art budget: accretion
  disk, lensing band, doppler-bright approaching side.
- Permanent landmark — always sensable, orienting all navigation.
- Owns the endgame: collapse ultimately feeds it; the terminal phase is
  its phase, whatever shape the endgame takes.
- Risk gradient toward it (deepest salvage near the horizon) makes the
  map's danger topology radial and readable.

### S9b — Side sketch: per-map field effects (EVE w-space model)

Separate exploration, not current work. Each map draws **one system-wide
field** (or none) from a field catalog — a global modifier applying to
everyone uniformly, like EVE wormhole-space effects (Pulsar, Magnetar,
Red Giant, Wolf-Rayet systems).

- **Constraint that keeps it cheap:** a field is a *preset vector over
  existing tunable contracts* (multipliers only — wave weight, signal
  propagation, drag, pulse cost/loudness, collapse rate). No new
  mechanics per field.
- Examples: Red Giant (waves +50%), Dark Nebula (signal carries half as
  far — the quiet universe), Ionized Fabric (pulses cheaper but louder),
  Dense Fabric (drag up, terminal down).
- Shown in the drop briefing → strategic layer at route select; fields
  favor different hulls/rigs, giving loadout choice meaning per run.
- Seeded per map; combined with the anomaly draw, "which universe is
  this" = field + anomaly cast.

## S11 — Mechanic Interaction Matrix + Build Order

Why signal was undiagnosable: it sits mid-web. The dependency truth:

```
movement ◄── fabric (coupling)        anomalies ──► fabric (signatures)
movement ◄── anomalies (gravity)      collapse ───► fabric (retune)
slingshot = movement verb ON anomalies
noise    ◄── movement (opposition)    noise ──► Inhibitor (pressure)
AI trio  ◄── noise (ears) + fabric (bodies ride it)
AI players ◄── ALL of the above (they play the whole game)
wrecks/portals/economy — edge systems, mostly independent
VFX/ruler — expression layer over everything, no dependencies inward
```

Live conflicts already resolved by this review: two-seas (S8), slingshot

## S12 — The Conductor + Inhibitor Clock v2 (replaces pressure)

**GREG design (2026-07-14), formalized.** The pressure integrator dies.
Match dramaturgy runs on deterministic seeded timers.

**The Conductor — a sim-controller module, not a feature.** Lives inside
the server sim controller alongside the other clock/math/sim processes.
Provides four generic primitives any system registers against:

1. **Threshold fields** — generalized `afterMinutes`: any spawner can
   declare "activate/increase after X" (more loot after X, more fauna
   after Y, inhibitor grace before phase 1). One mechanism, many users.
2. **Severity waves** — a generic scheduled spawn-wave primitive
   (cadence, budget, tier table). Inhibitor is its first consumer; fauna
   and loot pulses may use it too. Invariant: large/dangerous entities
   only ever arrive via an announced wave.
3. **Interval lerps** — between any two scheduled events, registered
   systems interpolate intensity (spawn frequency, VFX density): "between
   graceMinutes and wave 2, glitches increase." Events are the fronts;
   lerps are the drift between them.
4. **Offset guard** — registered timers never fire within `offsetGuard`
   seconds of each other. Inhibitor phases and wormhole windows interleave
   by construction, not hand-tuning.

**Inhibitor clock:** starts at zero on match start; match modifiers (S9b
fields) multiply values pre-generation. After grace, **three tunable
phases at even spacing**. Phase transitions are world events (register
change, corruption bloom). Waves escalate per interval by quantity and/or
tier; tiers gate entity classes (1 glitches/zones, 2 swarms/sentries,
3 hunters/vessel-class). Forms dissolve into tiers-of-entities: the
vessel is what the last wave brings, not a stage a meter reaches.

**Wormholes/portals redone on the same schema:** grace + evenly spread
open/close windows, different values, offset from inhibitor phases. Late
phases thin or shorten windows — extraction pressure rises with no new
mechanic.

**Pressure variable: deleted.** No meter, no band word — phases and
corruption are the read. Collapse epochs remain the separate universe
clock (also a Conductor client). **Signal/noise: not an input, very back
burner** — no wave-targeting hook until the rest is implemented (S10
stays tabled).

**Tunables:** graceMinutes (step 0.5), phaseInterval (step 0.5 min),
waveCadence (step 15 s), waveBudget (+N / +tier per interval), offsetGuard
(step 10 s), per-tier entity tables and lerp curves as data.

**Tests:** schedule reproducible from seed; big-entity-outside-wave =
failure; no registered events inside offsetGuard; HUD-less captures at
phase 0/1/2/3 orderable; lerped intensities monotone between their
endpoints.

## S13 — Hostile AI v2 (in review; Stellaris research pending)

**Feel target.** Thematic: scavengers are the ecosystem's professionals —
stripping this region long before you arrived, wanting the same salvage,
resenting competition. References: Rain World (creatures live their own
lives; you are not the center), Subnautica leviathans (territory +
telegraph; danger is geographic). Stellaris PVE/AI deep-dive running
before this section locks.

**GREG rulings (2026-07-14):**

1. **Multiple types, absolute speed classes.** Speeds designed in real
   units (m/s), NOT relative to the player — the game is moving toward

   referent. Level-banding entities to match joiners is a real future
   feature, parked whole. Start small; add modifiers later.
2. **Economy participation: yes.** They loot, carry, flee with, and drop
   haul. Killing one is a salvage decision.
3. **Telegraph: yes, with the MGS "!"** — a video-game-loud spotted

   type) are hidden information in play, but debug controls must

4. **Conductor delivery: broadly yes** — ambient via threshold fields,

5. **Body language: yes, with an execution caveat on record.** Greg has

**Tunables (absolute units):** per-type cruise/burst speed (m/s, step

**Tests:** territory probe (crossing a zone costs stated route

## S7 — AI Players (recovered founding design, in progress)

**Recovered truth (GREG, Q7):** there is no "single player" game. There is
only a multiplayer game; when matchmaking fails, the match fills with
**hostile AI players competing on the same stakes** as humans. This was
the original idea, hidden/lost in old designs — restored here as canonical.

Consequences:

- AI players are **rivals, not crewmates**. They play the same game:
  same wrecks, same portals, same signal exposure, same death and loss.
- **Systems peer, adversarial persona.** They occupy real seats and consume
  the same protocol/input contract as humans — no second code path; they
  inherit every consequence system for free and double as a permanent
  multi-seat test harness.
- This cleanly separates the AI trio:
  - **Fauna** — world texture, not on player stakes;
  - **Hostile AI (scavengers)** — world threats that punish noise but don't
    play the game;
  - **AI players** — rivals that DO play the game, with player verbs.
- Dread implication: another ship's signal bloom on your route means
  someone real-shaped is hunting the same prize. Presence of others is
  pressure even without contact.

**Deferred (GREG, 2026-07-14):** v0.4 is out of scope for this review — it
is a technical exploration and costing exercise that gets its own design
pass after v0.3 promotes to main. The pilots-vs-crews matchmaking question
and any crew/rival persona split belong to that pass. For v0.3.1, the AI
player system is designed as: rival pilots on the same stakes, same
protocol path (already true in code — AI players share the human movement
step; only brain and persona are missing).

## Red Flags Ledger

- **0.000x tuning constants** (Greg): e.g. `pressureFromTime: 0.0005/s`.
  Wrong units, hidden normalization, or an unfeelable knob. Audit all
  sub-0.01 sim constants; re-express in perceivable units (time-to-threshold,
  per-run totals).
- **Skill-vs-physics legibility** (Greg): player-usable skill effects are
  indistinguishable from ambient sim forces. Candidate rule: any player
  ability must move an observable outcome by a felt margin, provable by an
  A/B probe.

Decisions land here as questions resolve.

- **S1 (from Q1):** v0.3.1 scope = all systems to at least v2. Every entry in
  the audit table gets an original-intent check, a v2 goal, and a
  measurement before the release closes. Sequencing within the release can
  still prioritize the run-critical loop, but nothing is exempt.
- **S2 (from Q2):** inventory locked at 18 systems. Fauna, hostile AI, and
  AI players are separate designs with separate v2 bars — fauna
  = alive world, hostiles = respected threat, AI players = credible
  crewmate in the MP-first solo mode. VFX/UI-UX feedback is a first-class
  system so telegraphing has an owner.
- **S8a (GREG, 2026-07-14): the sea is authored, not simulated.** Ratified
  drift: fabric and movement have moved steadily away from an actual fluid
  simulation toward authored (still procedural) flow — and that is fine.
  The authoritative sea is parametric: authored terms, procgen seeds,
  event waves. The GPU Navier-Stokes sim is demoted from truth to
  paintbrush — a renderer of the authored field plus sub-floor texture.
  This is the Wave Race lesson (authored events + real physics response
  beat emergent fluid) and the jam maxim kept honest: fake the theorem,
  ship the feeling — but fake it in ONE place and let everything read it.
  **Non-negotiable rider (GREG):** authored parametric still means
  **randomized and seeded per match** — same seed, same sea; new match,
  new sea. Determinism from seeds is a hard requirement, not an
  optimization. Research closed (2026-07-14), scoped by Greg to v0.4
  multiplayer only and only if determinism were hard. **It is not hard:
  no engine.** Server-authoritative, one sim per match — determinism must
  hold on one Node process only, and the sim already has seeded RNG
  streams (`rng-stream.cjs`, integer-ops mulberry32, bit-identical) plus
  a fixed tick. Engines are net-harder: ~90% of LBH physics (coupling,
  wave bands, authored gravity, slingshot) stay custom callbacks anyway,
  no engine wraps a torus, and determinism becomes hostage to engine
  internals. Cheap guardrails for Codex instead: (1) replay-checksum
  test — run N ticks from a seed twice, hash state; (2) lint the sim
  path for bare `Math.random` (live `|| Math.random` fallbacks exist,
  e.g. `sim-runtime.cjs:3181`). If clients ever evaluate the sea locally
  from seed, hash-based noise or a bundled deterministic sin covers it —
  a hundred lines, not a migration.
- **S3 (from Q3): the v2 goal template.** Per system, in this order:
  1. **Feel target — two sentences.** (a) Thematic intent inside the game's
     fiction ("my ship can swing around a star to gain thrust because
     physics"). (b) A specific reference-game example with a clear rule set
     ("in Spider-Man I web-swing building to building and the game handles
     it within clear rules"). Greg's examples are illustrative, not
     binding — each system pass includes a short reference-research step to
     find the right comparison.
  2. **Tunables — minimal set, named, perceivable units.** As few as
     necessary (e.g. grapple distance, magnetism, coyote time). Tunables
     come first; the contract is built on them.
  3. **Test — goal-vs-tunables.** Can the feature hit the feel target using
     only the named tunables? If hitting the goal requires touching numbers
     outside the contract, the contract is wrong.
